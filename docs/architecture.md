# 構成

本サイトは、用語の定義をグラフから閲覧し、参照関係を複数の方法で分類・配置して比較できる静的サイトです。Issue #1 の本文とコメント 6072533111、6180078546 に記載された要件に基づいています。

## データの生成

`sources/` には原典の HTML と取得記録を保存します。`content/` には、原文のハッシュで対応付けた訳文と確認履歴を保存します。`npm run build:data` は、保存済みの原典を parse5 で読み取り、出典ごとの定義と参照の根拠を生成します。通常のビルドではネットワーク通信を行いません。

生成先の `src/generated/` は Git の管理対象から除いています。用語、出典ごとの定義、参照箇所を基礎データとして保持し、逆参照の一覧とグラフの辺はそこから作ります。原文中の位置は Unicode のコードポイント単位で数え、先頭を0とします。範囲の終了位置は、その範囲に含めません。画面の表示には、テキストと安全な DOM 操作を使います。

データの生成時には、原典 HTML のハッシュ、文書ごとの定義数、原文と訳文の対応、参照先、原文中の位置を検証します。用語数はデータから求めます。原文が変わった場合は、その原文に対応する新しい訳文が必要です。

`npm run check:upstream` は、最新の原典との差分を JSON 形式で報告します。保存済みの原典は上書きしません。内容が変わった場合や、取得・解析に失敗した場合は、0以外の終了コードを返します。

## 分類と配置

`src/analysis/` には、DOM やサイトの URL に依存しない TypeScript の計算処理をまとめています。

- `clustering.ts` は、無向・有向モジュラリティ、強連結成分、ラベル伝播、Louvain、スペクトル分類、2段階の map equation による分類を実装します。
- `layout.ts` は、グループ別、強連結成分の階層、層状、力学、距離ストレス、スペクトル、放射状、円形の配置を実装します。
- `graph.ts` は、入力を正規化し、辺の重複を除き、隣接関係と弱連結成分を求めます。
- `spectral.ts` と `numerics.ts` は、スペクトル分類・配置、対称 Jacobi 法、Cholesky 分解を実装します。
- `methods.ts` は、手法の説明、論文、設定項目、既定値を管理します。
- `worker.ts` は、画面の処理を止めずに計算を行い、分類と配置の結果を個別にキャッシュします。

分析には、選択中の出典と参照の種類に合う、方向付きの参照を使います。同じ用語間の参照は1つにまとめます。用語はすべて残し、条件に合う参照がない用語は孤立点として扱います。自己参照は分析の重みに含めませんが、閲覧用のグラフと根拠には残します。無向グラフを使う方式では方向も取り除き、さらに重複を除きます。出典や参照の種類が変わったら、分析に使う参照を更新し、Worker のキャッシュを無効にして分類と配置を再計算します。

分類処理は各用語が属するグループを、配置処理は各用語の座標を返します。7種類の分類と8種類の配置の全56通りについて、ノードの配列を保存することはありません。グループ別の配置では、選択中の分類に応じて座標が変わります。ほかの配置では、分類を切り替えても座標は変わりません。計算は必要になった時点で実行し、乱数シードと処理順を固定します。Node.js のテストとブラウザーの計算には、同じ実装を使います。

比較表の指標は、選択中の絞り込み条件と既定の計算条件で求めます。計算条件の変更や、手動で動かした座標は反映しません。モジュラリティ Q と符号長 L は異なる目的関数なので、数値を直接比べて順位を付けることはできません。各方式の実装範囲と限界は、設定画面と比較欄で説明します。

周辺表示には、選択した用語と、表示条件に合う直接隣接した用語から成る誘導部分グラフを使います。選択した用語を中央に置く専用の配置を使います。手動で動かした座標は分析結果とは別に保持し、出典と参照の種類の組み合わせごとに、全体表示と各用語の周辺表示で個別に保存します。ページを再読み込みすると、初期状態に戻ります。

## UI と再利用

`mountExplorer(container, options)` は、指定した領域にグラフ、設定、詳細欄を作ります。Cytoscape.js が描画と基本操作を、共有の分析モジュールが分類と配置の計算を担当します。各辺から、原文中のすべての参照箇所を確認できます。用語、参照、グループの HTML の一覧からも同じ情報を読めます。

グラフは、初期状態を受け取り、状態が変わると呼び出し側に通知します。サイトの URL や `document.body` は呼び出し側で管理します。CSS と DOM 操作の範囲は、指定した表示領域の内部に限定します。CSS のコンテナクエリーを使い、領域の幅に応じてグラフと詳細欄を左右または上下に配置します。

`src/site/` は、通常サイトの表示と URL の管理を担当します。`src/explorer/search.ts` は、グラフ内の検索と用語一覧を担当します。以前の用語集・サイト情報ページの `view` URL も、現在はグラフ画面で開きます。`embed.html` は、同じグラフ UI を単独で表示します。

`src/widget.ts` からは、原文データ、UI、計算処理、Worker をまとめた記事用の IIFE 形式の JS と CSS を生成します。Worker のコードは JS に含め、Blob から起動します。このため、別オリジンから JS を読み込む場合も、Worker を別の URL から取得する必要はありません。埋め込み先の CSP では、Blob からの Worker 起動を許可する必要があります。

通常サイトでは、選択した用語、出典、参照の種類、分類・配置方法、周辺表示、計算条件を URL に保持します。ズームと手動座標は、そのページを開いている間だけ保持します。`destroy()` は、Worker、ResizeObserver、描画に使うリソースを破棄します。埋め込み表示では、最初はページをスクロールする操作を有効にし、ボタンでグラフ操作に切り替えます。

## 配信と検証

Vite は、通常サイト、グラフ単独ページ、記事用の配布ファイルを `dist/` に生成します。CI では、型チェック、単体テスト、公開用ファイルに対する Playwright の操作・アクセシビリティ・描画性能の検証を実行します。すべて成功した成果物を GitHub Pages に公開します。

テストでは、小さな既知のグラフについて独立した計算を行い、目的関数、定常流、符号長、距離ストレスを確認します。全56通りで所属と座標がそろうこと、グループ別以外の配置が分類結果に依存しないことも検証します。ブラウザーでは、通常サイト、単独ページ、別オリジンに埋め込んだ配布ファイルの動作を確認します。
