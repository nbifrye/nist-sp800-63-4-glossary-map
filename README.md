# NIST SP 800-63-4 Glossary Map

NIST のデジタルアイデンティティガイドライン「SP 800-63-4」シリーズの用語集を読むための非公式サイトです。出典ごとの英語原文と日本語訳を読み、定義の中で原典が明示している、用語どうしの参照関係を確認できます。グラフの分類方法と配置方法をそれぞれ選び、結果を比較することもできます。

**[公開サイトを開く](https://nbifrye.github.io/nist-sp800-63-4-glossary-map/)**

日本語訳は、Codex が原文と照合して作成した本プロジェクト独自の訳です。NIST の公式訳ではなく、独立した人間による査読は行っていません。

## 使い方

トップ画面のグラフから用語を選ぶか、検索欄に英語の見出しを入力すると、出典ごとの定義を読めます。検索結果は上下キーと Enter キーでも選択できます。詳細欄を閉じると、グラフが画面いっぱいに広がります。

英語原文中の用語を選ぶと、その用語の定義に移動します。「参照する用語」「この用語を参照する定義」では、参照の根拠となった原文の表現、位置、出典を確認できます。検索と参照の対応付けには用語集の見出しを使い、略称一覧は使いません。

グラフでは全用語を見渡せるほか、選んだ用語の周辺だけを表示することもできます。用語を選ぶと定義が、線を選ぶと参照の根拠が表示されます。用語や参照、グループの一覧からも同じ情報を読めます。

- 分類方法は、無向モジュラリティ、有向モジュラリティ、強連結成分、ラベル伝播、Louvain、スペクトル分類、情報流の7種類です。
- 配置方法は、用語グループ別、強連結成分の階層、層状、力学、距離ストレス、スペクトル、放射状、円形の8種類です。
- 「表示設定」では、分類方法と配置方法を選び、出典で絞り込めます。グループの一覧、計算条件の変更、再計算、配置を初期状態に戻す操作もここにあります。
- 「手法を比較」では、分類結果や初期配置の指標を比較し、各手法の説明と論文を確認できます。

用語グループ別の配置は、選んだ分類に合わせて座標が変わります。ほかの配置方法では、分類を切り替えても座標は変わりません。出典を絞ると、その出典の定義にある参照を使って分類と配置を再計算します。全体表示では、参照のない用語も孤立した点として表示します。周辺表示では、選んだ用語と直接隣接した用語の部分グラフを対象に、選択中の方法と計算条件で分類・配置を計算します。表示範囲や選択した用語を変えると、計算し直します。

マウスやタッチ操作で表示を移動したり、拡大・縮小したりできます。用語をドラッグして動かすこともできます。グラフにフォーカスを合わせると、矢印キーで表示を移動し、＋／−キーで拡大・縮小し、0 キーで全体を表示できます。Shift＋矢印キーでは、選択した用語を動かせます。埋め込み表示では、最初はページをスクロールする操作が有効です。切り替えボタンを押すと、グラフを操作できます。

選択した用語、絞り込み条件、分類・配置方法、計算条件は URL で共有できます。ブラウザーの「戻る」「進む」でも復元されます。手動で動かした座標は、出典ごとに、全体表示と各用語の周辺表示で個別に保持します。ページを再読み込みすると、初期状態に戻ります。

## 参照関係と分類の読み方

矢印は、**定義のある用語から、その定義が参照する用語への参照**を示します。概念の依存関係や、推奨する学習順序を示すものではありません。

参照として扱うのは、原典が参照であることを明示している箇所だけです。

| 根拠 | 例 |
| --- | --- |
| 参照を指示する表現 | See、See also、Synonymous with に続く用語 |
| 用語集へのリンク | 原典で用語集の項目にリンクしている表現 |
| 原典の斜体表現 | 原典で斜体にしている用語 |

定義中に見出しと同じ語句があるだけでは、参照としません。同じ綴りでも別の意味で使われることがあり（「subject to」の subject、動詞の control など）、語句の一致だけでは参照かどうかを判断できないためです。

明示された箇所の中から見出しを探す際には、4文書すべての見出しを使います。単語の境界とハイフンを保って照合し、大文字と小文字の違いや連続する空白は無視します。単数形と複数形には、あらかじめ定めた変換規則を適用します。見出し末尾の括弧内の略称は照合から除き、略称、同義語、語幹から参照を推測することはありません。候補が重なる場合は、長い表現を優先します。

同じ見出しは1つの用語にまとめ、定義、訳文、参照の根拠は出典ごとに保持します。自己参照、循環する参照、文書をまたぐ参照も残します。原文中の位置は Unicode のコードポイント単位で数え、先頭を0とします。範囲の終了位置は、その範囲に含めません。

自動分類は、本プロジェクト独自の分析結果です。分析では自己参照と出典間で重複する参照を重みに含めず、無向グラフを使う方法では参照の方向も取り除きます。モジュラリティ Q と符号長 L は異なる目的関数なので、数値をそのまま比べて順位を付けることはできません。配置の指標は、選択中の表示範囲・絞り込み条件と既定の計算条件で求めた値です。計算条件を変えたり、手動で用語を動かしたりした後の値は反映されません。

情報流の分類には、2段階の map equation を使い、群の結合によって符号長を短くする方法を採用しています。公式 Infomap の探索処理や階層版は実装していません。層状配置には network simplex を使わず、距離ストレスの配置には重み付き stress majorization を使います。Newman のスペクトル分類とラプラシアンによる配置も比較できます。数式と出典は [手法と実装](docs/graph-research.md)、各手法の保証や限界、採用していない手法は [数学的な根拠と検証](docs/algorithm-review.md) を参照してください。

## ローカルで動かす

Node.js 24 以降を使います。

```sh
npm ci
npm run dev
```

[http://127.0.0.1:8765](http://127.0.0.1:8765) で表示できます。公開用のファイルを生成し、表示を確認するには、次のコマンドを実行します。

```sh
npm run build
npm run preview
```

通常のビルドでは、保存済みの原典からデータを生成します。公開するファイルは `dist/` に出力されます。ブラウザーで使うライブラリも同梱しているため、ビルド時の外部 API や、閲覧時の外部 CDN への通信は不要です。

```sh
npm test
npx playwright install --with-deps chromium firefox webkit
npm run test:browser -- tests/browser/explorer.spec.ts --workers=2
npm run test:browser -- tests/browser/performance.spec.ts --workers=1
```

ブラウザーテストは、公開用にビルドしたファイルに対して実行します。先に `npm run build` を実行し、手動で起動したプレビューサーバーを停止してください。Chromium、Firefox、WebKit、iPhone 相当の WebKit で、操作、アクセシビリティ、画面幅への対応、別オリジンでの埋め込みを確認します。実機と実際のスクリーンリーダーによる検証は含みません。

## 原典と訳文の更新

原典には、正式版 HTML の Glossary を使います。略称一覧は対象に含めません。

- [SP 800-63-4](https://pages.nist.gov/800-63-4/sp800-63.html#def)
- [SP 800-63A-4](https://pages.nist.gov/800-63-4/sp800-63a.html#def-and-acr)
- [SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html#def-and-acr)
- [SP 800-63C-4](https://pages.nist.gov/800-63-4/sp800-63c.html#def-and-acr)

```sh
npm run check:upstream > upstream-report.json
```

このコマンドは、最新の原典との差分を報告します。内容が変わっている場合や、取得・解析に失敗した場合は、0以外の終了コードを返します。保存済みのファイルは上書きしません。

1. `sources/` の対象 HTML を更新し、`manifest.json` の取得日、版、ハッシュ、件数を更新します。
2. 変更された原文の SHA-256 をキーとして、`content/translations.json` に原文、訳文、確認情報を追加します。古い項目は履歴として保持できます。
3. `content/reviews.json` に、対象の原文ハッシュ、確認対象、確認者、日時、結果、実施した確認と限界を記録します。
4. `npm run build` で抽出結果と参照の差分を確認し、単体テストとブラウザーテストを実行します。参照を対応付ける基準を変えた場合は、その版も更新します。

訳文だけを訂正する場合も、確認情報と確認履歴を更新します。データの生成時には、原典と各定義のハッシュ、原文と訳文の対応、出典ごとの件数、参照の根拠を検証します。原文に対応しない古い訳文や、抽出が不完全なデータがあれば、生成を中断します。

GitHub Actions はプルリクエストを検証します。`main` への push または手動実行では、検証に成功した `dist/` を GitHub Pages に公開します。リポジトリの Pages 設定では、**GitHub Actions** を選択してください。
