# NIST SP 800-63-4 Glossary Map

NIST のデジタルアイデンティティガイドライン、SP 800-63-4 シリーズの用語集を読む非公式サイトです。出典別の英語原文・日本語訳と、定義中の用語への参照関係を確認できます。グラフでは複数のクラスタリングと配置方式を独立して選び、結果を比較できます。

**[公開サイトを開く](https://nbifrye.github.io/nist-sp800-63-4-glossary-map/)**

日本語訳は Codex が作成し、原文と照合した本プロジェクト独自の訳です。NIST の公式訳ではなく、独立した人間による査読は行っていません。

## 使い方

「用語集」で英語の見出しを検索し、出典別の定義を読みます。英語原文中の用語を選ぶと、その定義へ移動できます。「参照する用語」「この用語を参照する定義」から、原文の表現・位置・出典を確認できます。略称一覧と略称による検索・対応付けは対象外です。

「関係グラフ」では全用語を俯瞰し、選択用語の周辺表示に切り替えられます。用語の選択で定義、線の選択で参照根拠を表示します。HTML の用語選択、参照一覧、群の一覧からも情報に到達できます。

- 分類：無向・有向モジュラリティ、強連結成分、ラベル伝播、Louvain、情報流の6方式。
- 配置：用語グループ別、強連結成分の階層、層状、力学、距離ストレス、放射状、円形の7方式。
- 「手法を比較」：分類結果、既定条件の配置指標、手法の説明と論文。
- 「表示設定・計算条件」：出典・参照種類の絞り込み、群の一覧、方式ごとの再計算、初期配置への復元。

群別配置を除き、分類を変えても座標は変わりません。表示を絞っても全体の分類と配置は維持します。局所表示は選択用語を中央に置く補助配置で、全体の配置方式とは区別します。

マウスやタッチでパン・ズーム・用語のドラッグができます。グラフにフォーカスすると、矢印キーでパン、＋／−でズーム、0で全体表示、Shift＋矢印キーで選択用語を移動できます。タッチ端末ではページスクロールとの切り替えボタンも使えます。埋め込みではページスクロールを優先します。

用語・検索条件・方式・計算条件は URL で共有でき、戻る・進むで復元できます。手動座標は全体・用語ごとの局所表示でページ内に保持し、再読み込みすると初期状態に戻ります。

## 参照関係と分類の読み方

矢印は **参照元の定義 → 定義中に登場する用語** を示します。概念上の必須の依存関係や、推奨学習順序ではありません。

| 種類 | 根拠 | 表示 |
| --- | --- | --- |
| 原典の明示参照 | See、Synonymous with、用語集リンク、原典の斜体表現 | 実線 |
| 独自の語句対応 | 上記以外の、定義中の表現と見出しの語句の一致 | 破線 |

4文書すべての見出しと、単語境界・ハイフンを保って照合します。大文字・小文字と連続空白を無視し、単数形・複数形の規則を適用します。末尾の括弧内略称を除き、略称・同義語・語幹から推測しません。重なる候補は長い表現を優先します。

同じ見出しは一つの用語にまとめますが、出典別の定義・訳文・参照根拠は保持します。自己参照・循環・文書をまたぐ参照も残します。原文位置は Unicode 文字単位、0始まり、終了位置を含まない範囲です。

自動分類は NIST の公式な分類ではありません。分析では自己参照と出典間の重複を重みに含めず、無向方式では方向も除きます。Q と符号長 L は異なる目的関数で、直接順位付けできません。配置指標は全用語・既定条件の値で、再計算・手動移動後の値ではありません。

情報流は2段階 map equation の貪欲結合で、公式 Infomap の探索・階層版ではありません。層状配置は network simplex を使わず、距離ストレスは Newton 法や厳密な majorization ではありません。詳しくは [手法と実装](docs/graph-research.md) を参照してください。

## ローカルで動かす

Node.js 24 以降を使います。

```sh
npm ci
npm run dev
```

表示先は [http://127.0.0.1:8765](http://127.0.0.1:8765) です。公開用ファイルは次のコマンドで確認できます。

```sh
npm run build
npm run preview
```

通常のビルドは保存済み原典から生成し、外部 API や通信を使いません。配信対象は `dist/` です。ブラウザーにも実行用ライブラリを同梱し、外部 CDN へのアクセスは不要です。

```sh
npm test
npx playwright install --with-deps chromium firefox webkit
npm run test:browser -- tests/browser/explorer.spec.ts --workers=2
npm run test:browser -- tests/browser/performance.spec.ts --workers=1
```

ブラウザーテストは公開用ビルドに対して実行します。先に `npm run build` を行い、手動のプレビューサーバーは停止してください。Chromium・Firefox・WebKit と iPhone 相当の WebKit を対象に、操作・アクセシビリティ・画面幅・別オリジンの埋め込みを確認します。実機と実際のスクリーンリーダーによる検証は含みません。

## 原典と訳文の更新

原典は正式版 HTML の Glossary です。略称一覧は含みません。

- [SP 800-63-4](https://pages.nist.gov/800-63-4/sp800-63.html#def)
- [SP 800-63A-4](https://pages.nist.gov/800-63-4/sp800-63a.html#def-and-acr)
- [SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html#def-and-acr)
- [SP 800-63C-4](https://pages.nist.gov/800-63-4/sp800-63c.html#def-and-acr)

```sh
npm run check:upstream > upstream-report.json
```

最新原典との差分を報告し、保存済みファイルは上書きしません。内容の変更や取得・解析の失敗は非ゼロ終了です。

1. `sources/` の対象 HTML と `manifest.json` の取得日・版・ハッシュ・件数を更新します。
2. 変更された原文の SHA-256 をキーに、`content/translations.json` へ原文・訳文・確認情報を追加します。古いエントリーは履歴として保持できます。
3. `content/reviews.json` に対象の原文ハッシュ、確認対象、確認者、日時、結果、実施した確認と限界を記録します。
4. `npm run build` で抽出と参照の差分を確認し、単体・ブラウザーテストを実行します。対応付けの基準を変える場合は基準の版も更新します。

訳文だけの訂正も、確認情報と確認履歴を更新します。原典・定義のハッシュ、原文と訳文の対応、出典別件数、参照根拠を生成時に検証し、古い訳文や不完全な抽出を正常なデータとして配信しません。

## 埋め込みと公開

`embed.html` はグラフ単独ページです。`dist/widget/` の JS/CSS はデータと Worker を同梱した配布物で、CodePen などから読み込んで利用できます。Zenn 向けの手順と固定版の作り方は [埋め込み](docs/embedding.md) を参照してください。

GitHub Actions はプルリクエストで検証し、`main` への push または手動実行で、検証に成功した `dist/` を GitHub Pages に公開します。Pages 設定は **GitHub Actions** を選択してください。
