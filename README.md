# NIST SP 800-63-4 Glossary Map

NIST SP 800-63-4 正式版4文書の Glossary を横断して読む、非公式の静的サイトです。

**公開サイト：[Glossary Map](https://nbifrye.github.io/nist-sp800-63-4-glossary-map/)**

189用語・496件の文書別定義と日本語訳を収録し、原文中の1,706出現を参照関係として保存しています。検索、出典絞り込み、原文の語句からの移動、出典別の参照先・参照元一覧、全体／局所の方向付きインタラクティブグラフ、定義の共有リンクを利用できます。全体グラフは全189用語・512本の方向付き関係を同時表示し、同じ方向の全1,706出現を出典別に追跡できます。ズーム・平行移動・ノードのドラッグ、キーボード操作、タッチ操作に対応します。全参照は一覧でも確認できます。

## 原典と編集内容

2026-10-09 に取得した [NIST HTML 版](https://pages.nist.gov/800-63-4/)の正式版（Revision 4, 2025）を使用します。各文書の Glossary のみを抽出し、略称一覧は含みません。

| 文書 | Glossary アンカー | 定義数 |
| --- | --- | ---: |
| SP 800-63-4 | `def` | 189 |
| SP 800-63A-4 | `def-and-acr` | 89 |
| SP 800-63B-4 | `def-and-acr` | 124 |
| SP 800-63C-4 | `def-and-acr` | 94 |

同じ見出しは1ノードにまとめます。定義 ID、出典、原文、原文ハッシュ、参照の根拠は文書ごとに独立しています。4文書の同一定義は同じ訳文を使いますが、出典を混同しません。定義全文の空白を正規化し、複数段落・箇条書きも全内容を保持します。保存 HTML との独立した件数・全文照合をテストで行います。

日本語訳は Codex が原文と対照確認したプロジェクト独自の訳です。**NIST の公式訳ではなく、独立した人間による査読は未実施です。** 翻訳、斜体・リンク情報、参照判断には原文の SHA-256 が紐付きます。内容確認記録は `data/review-history.json`、変更履歴は Git に保持します。

## 対応付け基準

`heading-longest-boundary-v1` は、全4文書の見出しを対象に原文の語句を照合します。

- 見出し末尾の括弧内略称（例：`(CSP)`）は除いて照合・検索します。略称単独の別名検索や対応付けはしません。見出しそのものに含まれる `RP subscriber account` などの表現は、その見出し全体で照合します。
- 大文字・小文字と連続空白は同一扱い。単語境界を要求し、ハイフンを保持します。`authentication` は `reauthentication` や `multi-factor authentication` の部分としては拾いません。
- 単複形は末尾語の規則（`s`、`es`、子音＋`y` ↔ `ies`）と限定した不規則形（person/people など）で扱います。語幹・略称・同義語からの推測はしません。多義語や形態上の一致は意味の同一性を保証しません（例：`control` と `controls`）。これも独自の語句対応として表示します。
- 重なる候補は最長表現を優先し、同じ範囲の短い複合語・単語は重複登録しません。自己参照は保持します。循環は再帰展開せず、全体図では全関係、局所図では選択用語と直接接続する全用語・その間の関係を表示します。
- `See …`（接続詞で連なる参照を含む）、`Synonymous with …`、Glossary への明示リンクを**原典の明示参照**とします。それ以外の語句一致は**独自の語句対応**です。斜体だけでは明示参照にしません。なお、明示参照でも単複形や見出しへの対応は本プロジェクトの基準で行います。
- 各出現に原文表現、開始・終了位置（Unicode 文字、0始まり、終了位置は範囲外）、対応先ノード、判断規則、原典の斜体情報を保存します。参照元の定義から出典を追跡できます。

**これらはテキスト上の参照であり、概念上の必須の依存関係や推奨学習順序ではありません。**

## 全体グラフと自動検出された用語群

ページ上部のグラフで全用語を俯瞰し、「選択用語の局所グラフ」で1ホップの近傍に切り替えます。局所図は選択用語を中央に、隣接用語を同心円状に置きます。局所図の隣接用語間の関係も表示します。全体・局所の手動配置はメモリ内で別々に保持し、選択やモード切り替えだけでは失われません。「配置を戻す」で現在のモードの自動配置に戻せます。再読み込み時は配置を初期化します。

背景のドラッグで平行移動、ホイール／ピンチ／ボタンでズームできます。ノードをドラッグすると接続線と群の背景も追随します。用語をクリックまたは Enter で詳細へ移動します。グラフ自身の矢印キーは平行移動、＋／−はズーム、0は表示中の全用語に合わせます。用語にフォーカスしたときの矢印キーはその用語の配置を移動します。「用語へズーム」から直接ノードへ移動でき、「参照関係の根拠を見る」からキーボードで全関係の出典を探索できます。

参照は方向付きの用語ペアごとに集約しますが、出現や出典を削除しません。線の選択で、すべての原文表現・文書別定義・原文位置・対応先を確認できます。明示参照と独自の語句対応を実線・破線で分け、両方を含む関係は平行した線で示します。参照元の文書・種類による絞り込みはグラフにも適用されます。全体モードでは絞り込み時も189ノードを残し、表示件数と条件を明記します。

用語群は `greedy-modularity-undirected-unique-v1` により、**自己参照を除く一意な無向用語ペア**から決定論的に検出します。文書間の同じ定義の反復、出現回数、方向、明示／独自の種別は群の重みには使いません。単独ノードを含む21群を生成し、モジュラリティは0.527101です。各群で関係数の多い上位3用語を探索用の見出しにします。これは意味を人手で分類した名称ではありません。群番号は用語数順で、保証レベルや優先順位を示しません。

**自動検出された群は NIST の公式な分類ではありません。** 所属は全原典データで検出し、出典・参照種類のフィルターや自由配置では再分類しません。群を選ぶと構成用語と群内の方向付き関係を列挙し、元の文書別根拠へたどれます。他の群を暗く表示しますが、全体図からノードや参照を削除しません。

`cluster-phyllotaxis-v1` は群内に重なりのない初期位置を置き、群の区画を詰めて配置します。全体図ではラベルの重複を避け、低倍率では主な用語だけを表示します。全ノードの名前はホバー、キーボードフォーカス、用語検索、群の一覧で確認できます。配置・所属は `data/layout.json` に原典データの SHA-256 とともに保存し、ビルドで再現性を検証します。実行中に力学シミュレーションを走らせず、平行移動・ズームをフレーム単位でまとめ、平行移動時はテキストを再計算せず、ズーム時は表示するラベルだけ更新し、ノード・参照線・ラベルは Canvas でまとめて描き、用語ごとの操作対象を SVG、検索・関係選択・根拠一覧を HTML で提供します。キーボードのフォーカスも Canvas 上に描画します。

## 開発・検証

公開サイトには外部ライブラリ・外部フォント・外部 API が不要です。ビルドは Python 3.11+ の標準ライブラリのみ。テストには Node.js 24 と開発用 Playwright を使います。

```sh
npm ci
npm run build
npm test
npx playwright install --with-deps chromium firefox webkit
npm run test:browser
python3 -m http.server 8765 --bind 127.0.0.1
```

ローカルで `http://127.0.0.1:8765` を開きます。`file://` では JSON の取得が制限されるため HTTP を使ってください。

ブラウザーテストは Chromium、Firefox、WebKit、および iPhone 相当の WebKit 表示を対象に、検索、出典切り替え、根拠、循環参照、グラフ移動、定義リンク、キーボード、axe による WCAG 2.1 AA 検査、狭い画面、読み込み失敗を確認します。モバイル実機・実際のスクリーンリーダーによる全操作の検証は含みません。拡大表示は狭い CSS ビューポートでリフローを検証します。グラフ内を平行移動できます。

## 原文更新・訂正

```sh
python3 scripts/check_upstream.py > upstream-report.json
```

このコマンドは NIST から最新 HTML を取得し、追加・削除・定義ハッシュの変化を報告します。公開原文や訳文は上書きしません。通信・解析に失敗したとき、あるいは定義が変わったときは成功扱いにしません。

更新時は、正式版・取得日を確認して `sources/` の対象 HTML と `manifest.json`（SHA-256、件数、版）を更新します。変更された英語定義は新しいハッシュで `translations.json` に訳・作成者・確認情報を追加し、旧エントリーは履歴として残します。`build.py` は原文に合う訳が存在しなければ失敗します。対応付けの差分も確認し、`review-history.json` に範囲、理由、確認者、実施した確認と未実施の査読を追記します。`tests/test_data.py` と `core.mjs` の固定件数も確認後に更新し、配置と自動群も再生成・確認し、全テスト・コミットを行います。

訳文の訂正は該当原文ハッシュのエントリーを編集し、確認記録を更新して再生成します。基準の変更はルールバージョンを更新して全参照差分を再確認します。公開時に外部原典を自動取り込みしないため、意図せず未確認の内容に置き換わることはありません。

## 公開と保護

GitHub Actions の `Verify and deploy Pages` が `main` への push 後にビルド、原文・データ・ロジック・ブラウザー検証を行い、成功した静的ファイルのみを GitHub Pages に公開します。PR では検証だけ実行します。リポジトリの Pages 設定は **GitHub Actions** を選びます。手動実行も可能です。

性能測定ではブラウザー内で連続描画を計測し、テスト制御の通信往復と画面トレースの追加負荷を除外し、CIでは各ブラウザーを1つずつ起動して測定します。機能・アクセシビリティ検証では失敗時のトレースを保持します。

公開ファイルは `scripts/package_site.py` の許可リストで限定します。原典の HTML、開発依存、テスト、設定ファイルは公開物に含めません。データは DOM のテキストとして描画し、HTML として挿入しません。CSP は同一オリジンのスクリプト・スタイル・データに限定します。データ形式、件数、参照先・根拠位置が不正なら閲覧結果を出さず、エラーと再読込を提示します。デプロイジョブだけに Pages 書き込み権限を付与します。
