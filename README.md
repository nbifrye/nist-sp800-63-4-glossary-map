# NIST SP 800-63-4 Glossary Map

NIST のデジタルアイデンティティガイドライン、SP 800-63-4 シリーズの用語集をまとめて読める非公式サイトです。4 文書の英語原文と日本語訳を出典別に掲載し、定義に登場する用語のつながりを一覧とグラフで確認できます。

**[公開サイトを開く](https://nbifrye.github.io/nist-sp800-63-4-glossary-map/)**

収録内容は 189 用語、出典別の定義 496 件です。定義中の用語を対応付けた箇所は 1,706 か所あり、グラフでは参照元と参照先の組み合わせごとに 512 本の矢印にまとめています。

日本語訳は Codex が作成し、原文と照合した本プロジェクト独自の訳です。**NIST の公式訳ではありません。独立した人間による査読も行っていません。**

## 使い方

画面上部の「用語集」「関係グラフ」「サイト情報」で表示を切り替えます。

### 用語の定義を読む

1. 「用語集」で英語の見出しを検索し、用語を選びます。「出典文書で絞る」で対象の文書を指定できます。
2. 出典別の日本語訳を読みます。英語原文や翻訳の確認履歴は、必要に応じて開いて確認できます。
3. 「参照関係」に切り替えると、その用語が参照する用語と、その用語を参照している用語を調べられます。参照一覧は 8 件ずつ表示し、各項目から出典と原文の該当箇所を確認できます。

英語原文中の参照用語を選ぶと、その定義へ移動できます。選択した用語、出典、検索条件、参照一覧の方向やページは URL に反映されるため、リンクの共有やブラウザーの「戻る」で同じ表示に戻れます。

検索の対象は英語の見出しです。見出し末尾の括弧内にある略称は検索対象に含めず、略称だけの検索には対応していません。

### グラフでつながりを見る

「関係グラフ」では全用語を表示します。用語を選び、「周辺の用語」に切り替えると、選択した用語に直接つながる用語と、それらの間の参照関係を表示します。

用語を選ぶと、同じ画面の詳細パネルに出典別の定義を表示します。線を選ぶと、その参照関係に含まれる原文の表現・位置・出典を確認できます。詳細パネルは、広い画面ではグラフの横、狭い画面では下に表示します。

| 操作 | マウス・タッチ | キーボード |
| --- | --- | --- |
| 用語を選ぶ | クリック・タップ、または「用語を探す」から選択 | 用語にフォーカスして Enter |
| 表示位置を動かす | 背景をドラッグ | グラフにフォーカスして矢印キー |
| 拡大・縮小する | ホイール、ピンチ、＋／− ボタン | グラフにフォーカスして ＋／− |
| 表示中の全用語を収める | 「全体を表示」 | グラフにフォーカスして 0 |
| 用語の位置を変える | 用語をドラッグ | 用語にフォーカスして矢印キー |

「表示設定」では出典や参照の種類を絞り込み、用語群を選択できます。「操作ガイド・参照一覧」から、線を直接選ばずに参照の根拠を調べることもできます。全体表示では、参照を絞り込んでも全 189 用語を残します。

タッチ端末では、グラフ内の 1 本指の移動・ドラッグと 2 本指のピンチが有効です。グラフ上でページをスクロールする操作にも切り替えられます。

手動で変えた配置は、全体表示と用語ごとの周辺表示でそれぞれ保持します。用語や画面を切り替えても残りますが、ページを再読み込みすると初期配置に戻ります。「ノードの配置を初期状態に戻す」でも現在の表示の配置を戻せます。

## 参照関係の読み方

矢印は **参照元の定義 → 定義中に登場する用語** を表します。概念上の依存関係や、推奨される学習順序を示すものではありません。

| 種類 | 判定の根拠 | グラフの表示 |
| --- | --- | --- |
| 原典の明示参照 | `See …`、`Synonymous with …`、用語集へのリンク、原典で斜体になっている用語表現 | 実線 |
| 独自の語句対応 | 上記に当てはまらない、定義中の表現と見出しの語句の一致 | 破線 |

同じ方向の関係に両方の種類が含まれる場合は、線を並べて表示します。線にまとめても、各文書の定義や原文中の該当箇所は省略しません。

対応付けの基準は `heading-longest-boundary-v2` です。

- 4 文書すべての見出しと照合します。参照元の文書に載っていない用語も対象にします。
- 大文字・小文字と連続する空白の違いを無視します。単語の境界とハイフンは保ち、別の単語の一部に当たる文字列は拾いません。
- 見出し末尾の括弧内略称を除いて照合します。略称・同義語・語幹から対応先を推測しません。
- 単数形・複数形は語尾の規則と一部の不規則形で照合します。ただし、形が一致しても意味が同じとは限りません。
- 重なる候補は長い表現を優先します。たとえば `multi-factor authentication` に対応する箇所で、内部の `authentication` を別の参照として重複登録しません。
- 斜体かどうかは該当箇所ごとに判定します。明示参照の場合も、見出しとの対応は本プロジェクトの基準によります。
- 自分自身への参照や循環する参照も残します。

各箇所には原文の表現、対応先、判定規則、斜体の情報、開始位置と終了位置を保存しています。位置は空白を正規化した原文の Unicode 文字単位で、0 から数え、終了位置の文字は範囲に含めません。

## 用語群と配置の比較

「手法を比較」では、用語群の検出方法とグラフの配置方法を別々に選べます。用語群は参照関係から自動で求めたもので、**NIST の公式な分類ではありません。**

| 用語群の検出方法 | 群の数 |
| --- | ---: |
| 無向モジュラリティ | 21 |
| 有向モジュラリティ | 19 |
| 強連結成分 | 152 |
| ラベル伝播 | 12 |
| Louvain | 19 |
| 情報流（map equation を用いた貪欲法） | 21 |

配置は、用語群別、強連結成分の階層、Sugiyama 系の層状配置、力学配置（Fruchterman–Reingold）、距離ストレス、放射状、円形の 7 方式です。検出方法との組み合わせで 42 通りを比較できます。

用語群の検出には全出典の参照を使い、自己参照と文書間で重複する関係は分析の重みに含めません。出典や参照の種類で表示を絞り込んでも、群の所属は変わりません。「グループの用語一覧」で構成用語と群内の参照関係を確認できます。

通常は保存済みの配置を使います。方式ごとの計算条件を調整して「再計算」すると配置を更新し、「初期値に戻す」で保存済みの配置を復元します。比較表の交差数や線の長さは初期配置の値で、絞り込み・再計算・手動移動後の値ではありません。

各方式の目的、論文、実装上の省略、指標の読み方は [論文調査と実装の対応](docs/graph-research.md) にまとめています。情報流の方式には公式 Infomap の探索処理を使っておらず、距離ストレスも参照論文の手法をそのまま実装したものではありません。

## 原典と収録範囲

2026 年 10 月 9 日に取得した正式版（Revision 4、2025 年）の HTML を使用しています。対象は各文書の Glossary（用語集）で、略称一覧は含みません。

| 原典の用語集 | 定義数 |
| --- | ---: |
| [SP 800-63-4](https://pages.nist.gov/800-63-4/sp800-63.html#def) | 189 |
| [SP 800-63A-4](https://pages.nist.gov/800-63-4/sp800-63a.html#def-and-acr) | 89 |
| [SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html#def-and-acr) | 124 |
| [SP 800-63C-4](https://pages.nist.gov/800-63-4/sp800-63c.html#def-and-acr) | 94 |

同じ見出しは 1 つの用語にまとめ、定義と出典は文書ごとに保持します。同じ原文には同じ訳文を使います。原文は空白を正規化していますが、段落や箇条書きの内容はすべて収録しています。

原典 HTML と定義ごとの SHA-256 ハッシュを記録し、訳文を対応する原文のハッシュに紐付けています。原文が変わった場合、古い訳文をそのまま引き継いでビルドすることはできません。翻訳や対応付けの確認記録は [data/review-history.json](data/review-history.json)、変更履歴は Git に残しています。

## ローカルで動かす

ビルドには Python 3.11 以降の標準ライブラリを使います。テスト環境は Node.js 24 と Playwright です。公開サイトの利用には JavaScript が必要ですが、外部ライブラリ・外部フォント・外部 API へのアクセスは不要です。

```sh
npm ci
npm run build
python3 -m http.server 8765 --bind 127.0.0.1 --directory _site
```

[http://127.0.0.1:8765](http://127.0.0.1:8765) を開きます。`file://` ではデータを取得できないため、HTTP サーバーを使ってください。ビルドすると、用語データと初期配置を生成し、公開用ファイルを `_site/` にコピーします。

### 検証する

```sh
npm test
npx playwright install --with-deps chromium firefox webkit
npm run test:browser
```

`npm test` は原典と収録データの件数・全文照合、参照の根拠、用語群の分析、配置、JavaScript の処理を検証します。

ブラウザーテストは Chromium、Firefox、WebKit、iPhone 相当の WebKit 表示を対象に、検索、参照の確認、グラフ操作、キーボード操作、画面幅への対応、読み込み失敗、描画性能を検証します。axe による WCAG 2.1 AA の自動検査も含みます。モバイル実機や実際のスクリーンリーダーによる全操作の検証は行っていません。

Playwright はリポジトリ直下を配信する HTTP サーバーを自動で起動します。公開用ファイルの確認後にブラウザーテストを行う場合は、先に手動で起動したサーバーを停止してください。

## 原文の更新と訳文の訂正

最新の原文との差分は、次のコマンドで確認できます。

```sh
python3 scripts/check_upstream.py > upstream-report.json
```

NIST から HTML を取得し、用語の追加・削除、定義の変更、HTML 全体の変更有無を報告します。保存済みの原典や訳文は上書きしません。用語や定義に変更がある場合、または通信・解析に失敗した場合は、終了コードが 0 以外になります。

原文を更新する場合は、次の手順で確認します。

1. 正式版と取得日を確認し、`sources/` の対象 HTML と `sources/manifest.json` の取得日・版・ハッシュ・件数を更新します。
2. 変更された定義の新しいハッシュをキーに、`data/translations.json` へ原文・訳文・確認情報を追加します。旧エントリーは履歴として残します。
3. 参照の対応付けの差分を確認し、`data/review-history.json` に確認範囲、理由、確認者、実施した確認と未実施の査読を記録します。
4. 件数が変わった場合は `tests/test_data.py` と `core.mjs` などの固定件数も見直します。対応付けの基準を変えた場合は、基準のバージョンを更新し、すべての参照の差分を確認します。
5. `npm run build` でデータ・用語群・配置を再生成し、差分と表示を確認します。単体テストとブラウザーテストを実行してからコミットします。

訳文だけを訂正する場合は、該当する原文ハッシュの訳文と確認情報を編集し、確認履歴を追記して再生成・検証します。公開時に外部の原文を自動で取り込む処理はありません。

## GitHub Pages への公開

GitHub Actions の `Verify and deploy Pages` は、`main` への push 後にビルドと各種テストを実行し、成功した場合に `_site/` を GitHub Pages へ公開します。プルリクエストでは検証だけを行います。手動実行も可能です。リポジトリの Pages 設定では **GitHub Actions** を選択してください。

CI では生成した用語データ・配置がコミット済みの内容と一致することも確認します。描画性能の測定は、ブラウザーを 1 つずつ起動して実施します。

公開対象は [scripts/package_site.py](scripts/package_site.py) に列挙したファイルです。原典 HTML、開発用の依存パッケージ、テスト、設定ファイルは含めません。画面にはデータを HTML として挿入せず、テキストとして表示します。CSP でスクリプト・スタイル・データの取得元を同一オリジンに制限し、Pages への書き込み権限は公開ジョブだけに付与しています。
